# ReadGS1AI_Expo

Demonstrates how to recognize and parse GS1 Application Identifiers (AIs) from barcodes, extracting and formatting fields such as dates and other AI data.

## What This Sample Does

- Loads a custom processing template from `assets/Templates/ReadGS1AI.json` with `cvr.initSettings()`, which enables the GS1 AI parser on top of barcode decoding
- Receives structured output through `onParsedResultsReceived` instead of raw barcode text
- Walks the flat `parsedFields` map, where each AI contributes a pair of entries — `${ai}AI` for the description and `${ai}Data` for the value — collects the distinct AI prefixes, and prints them in an `Alert`
- Skips fields whose `validationStatus` is `VS_FAILED`, so invalid AI data never reaches the UI
- Normalizes date and time AIs that use the `yyMMdd`, `yyMMddHHmm` or `yyMMddHHmmSS` form into `yy/MM/dd`, `yy/MM/dd HH:mm` and `yy/MM/dd HH:mm:ss`, including the GS1 rule that day `00` means the last day of the month

The parsing helpers (`isAI()`, `parseDateAndTimeString()`, `getContentsFromParsedItem()`) are plain TypeScript and can be lifted into your own project as they are.

## Requirements

- A recent Node.js LTS release
- An Expo project with native project generation (`npx expo prebuild`); the Expo, React Native and React versions are declared in `package.json`
- A physical iOS or Android device with a camera — the sample relies on live camera input and is not meant to run on a simulator
- Dynamsoft packages, already listed in `package.json`:
  - `dynamsoft-barcode-reader-bundle-react-native`
  - `dynamsoft-capture-vision-react-native`
- `expo-build-properties`, the Expo config plugin used to apply the Android build settings described in the integration notes below

## How to Run

1. Enter the sample folder

```bash
cd ReadGS1AI_Expo
```

2. Install node modules

```bash
yarn install
```

or

```bash
npm install
```

3. Generate native projects

Run the following command to generate the `android` and `ios` folders:

```bash
npx expo prebuild
```

4. Prepare iOS

Install the necessary native frameworks from CocoaPods:

```bash
cd ios
pod install
cd ..
```

5. Build and run

- **Android**

```bash
npx expo run:android
```

- **iOS**

```bash
npx expo run:ios
```

If everything is set up _correctly_, the camera opens immediately. Point it at a GS1 barcode (for example a GS1-128 with an expiration date) and the parsed AI list appears in an `Alert`.

> [!NOTE]
> This sample uses native modules, so it does **not** run in Expo Go. You must build a development build with `npx expo run:android` or `npx expo run:ios`.

> [!NOTE]
> The application needs to run on a physical device rather than a simulator as it requires the use of the camera.

## Integration Notes For Your Own Project

### Android: configure `expo-build-properties`

Because the native projects are generated by Expo, Gradle settings cannot be edited by hand — they are regenerated on every `prebuild`. Instead, declare them in `app.json` through the `expo-build-properties` plugin:

```json
{
  "expo": {
    "plugins": [
      [
        "expo-build-properties",
        {
          "android": {
            "cmakeVersion": "3.31.6",
            "extraMavenRepos": [
              "https://download2.dynamsoft.com/maven/aar"
            ]
          }
        }
      ]
    ]
  }
}
```

- `cmakeVersion` — the Dynamsoft native libraries are built with CMake. The Android Gradle Plugin defaults to CMake 3.22.1, which bundles ninja 1.10.2; that ninja cannot handle paths longer than 260 characters, so builds break as soon as the project lives in a deep directory on Windows. CMake 3.31 and later bundle ninja 1.12, which supports Windows long paths.
- `extraMavenRepos` — registers Dynamsoft's Maven repository so the native Android artifacts can be resolved during the build.

The plugin only runs during prebuild, so after editing `app.json` regenerate the native projects:

```bash
npx expo prebuild --clean
```

### iOS: camera permission

The camera is opened from native code, so iOS requires a usage description. With Expo, declare it in `app.json` instead of editing `Info.plist` — prebuild writes the entry into the generated plist for you:

```json
{
  "expo": {
    "ios": {
      "infoPlist": {
        "NSCameraUsageDescription": "This app requires camera access to scan barcodes."
      }
    }
  }
}
```

- The value is shown to the user in the permission prompt, so describe your own use case instead of copying the sample text verbatim.
- Without this key the app is terminated by the system the first time it touches the camera, and App Store review will reject the build.
- Any manual edit you make to `ios/*/Info.plist` is lost on the next `prebuild`, so always keep the key in `app.json`.
